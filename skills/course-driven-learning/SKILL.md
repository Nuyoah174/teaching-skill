# 课程驱动学习

这是一套可供老师、协作者或其他 agent 接手时复用的教学方法。完整偏好、操作流程和更新步骤都在 [教学规范](../../TEACHING_GUIDELINES.md)。本文件只保留交接时先抓住的要点。

## 何时使用

- 新老师或其他协作者按同一套偏好接手教学，且不重置已有进度。
- 安排课程补基础、集中实践、当日任务或一周计划。
- 验收学习者能否独立演示、独立修改并讲清机制。
- 学习者反复卡住，需要判断缺的是哪一项前置知识。
- 当天收束，或把学习者明确提出的新偏好合并进规范。

具体课表、当日进度、学习者身份与环境信息另册维护，不写在本技能里。

## 要点

- **宏观先行。** 先说明实际项目场景、完整任务链，以及今天的内容落在哪一环、解决什么问题，再进入原理、代码和练习。
- **课程补基础，集中实践。** 课程负责系统补基础。老师负责目标拆解、课后检验、集中实践、排错，以及课上未覆盖但项目必须补的机制。集中实践不拖到整套课程看完才开始。
- **独立演示、独改、解释验收。** 约定成果要同时满足：可以看自己的笔记、不靠逐行提示，复现完整流程；独立改一个参数或小要求，先预测再验证；用自己的话说明输入如何变成输出、关键步骤为何需要、失败时先查什么，以及它在目标项目链中的位置。跟着练过、看完视频或听懂解释，都还不是独立掌握。
- **前置缺口诊断。** 反复讲解后仍然卡住时，先诊断缺的是哪一项前置知识，说明它和当前问题的关系、补到什么程度就可以回到原任务。补完再继续。
- **日终对照计划。** 宣布当天学习结束前，对照现有规划逐项核对该日全部任务，分开完成、未完成和阻塞。不能漏项后直接结束，也不能在未说明的情况下把剩余任务顺延到第二天。
- **事实核验。** 未核实的链接、集数、时长和代码结论不要写成已确认事实。讲解内容要分开：已实际获取并核对、只核实了配套源码或目录、尚未获取。访问失败如实说明。
- **先读 GitHub 最新版再更新。** 规范入口已经确定，不必每次重新选择仓库。仓库是 https://github.com/Nuyoah174/teaching-skill ，路径是 `TEACHING_GUIDELINES.md`，默认分支是 `main`，可见性是 private。更新前先读取 `main` 上该文件的最新版本和提交 SHA，再合并本次明确提出的新偏好；有冲突时先处理冲突，不整篇覆盖。保留简短变更记录，提交后核对内容并交付提交链接。合并进入 `main` 之后，该文件才是权威入口；尚未合并的拉取请求是待采用版，要明确说尚未进入 `main`。
